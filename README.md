# Tandem

Personal Agent 的 M4 开发版本：原生 SwiftUI 聊天、多模型接入、项目与上下文管理、持久任务、原生只读文件工具、审批与执行预算、可追溯的事实与决策记忆。SwiftUI App 管理 Node Runtime，通过受保护的 Unix Domain Socket 通信。产品基线见 [产品与技术设计规范](docs/Personal_Agent_产品与技术设计规范_v1.0.md)。

## 开发环境

- Apple Silicon Mac；最低部署目标 macOS 14.0。本机验证环境为 macOS 27.2，未在 macOS 14 实机运行。
- Xcode 27.2 / Swift 6.4.2（SPM 使用 Swift 5 语言兼容模式）。
- Node **24.22.2**，pnpm **11.22.0**；TypeScript 和类型依赖已锁定。

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm run typecheck
pnpm run test
pnpm run dev
```

`build` 生成 `dist/Tandem.app`，内含当前已验证的 arm64 Node 可执行文件和编译后的 JavaScript；运行应用包不依赖 pnpm、工作目录或全局 Node。`dev` 构建后打开应用；也可直接打开该 `.app`。这是未做正式签名、公证的本地开发包。

## 使用

1. 打开“模型设置”，添加供应商并填写自定义名称，选择协议和 API 类型，填写 API Base URL、Key，再逐项添加模型。
2. 选择并保存全局默认模型，或在输入框上方手动选择已配置模型。未设置默认时不会自动选用列表第一项。供应商名称只用于显示，内部 ID 保持稳定；删除默认模型会清空默认选择。
3. 在 Assistant 输入消息。支持普通与流式文本响应，同话题的消息按顺序排队；失败后可使用原模型重试，或手动换模型再重试。
4. 使用“新话题 / 临时插话”标记下一条输入；临时讨论后可点击“恢复原话题”。最近话题侧栏可恢复历史讨论。Assistant 展示一份全局历史，话题标签说明每条消息的归属；发给模型的内容只包含当前话题的因果历史。

5. 在“项目”创建、编辑、归档或恢复项目；也可输入完整命令“创建一个旅行项目”。单纯提到主题不会自动创建项目。
6. 在输入区选择 automatic / pinned / isolated 及项目，点击“应用范围”。isolated 未指定项目时输入保持待确认；候选和模型上下文不会自动使用全局或其他项目内容。
7. 遇到“待确认话题”卡片，选择候选或新话题后才会发送模型请求。可按项目筛选全局历史，纠正单次交互的项目归属，查看原执行上下文，并手动按新归属重新处理。
8. 项目永久删除使用独立预览和确认入口。归档保留历史；永久删除清理相关历史及快照片段，保留共享会话中的其他交互，不删除外部文件。

9. 需要持续工作时勾选输入区“持续任务”，填写交付物和逐条完成标准。Activity 可查看执行、修改任务形成新修订、打开与复制 Markdown 报告；普通回答结束不等于任务完成。
10. 在 Activity 点击“授权只读目录”，选择当前项目目录后可读取 UTF-8 文本。支持有界枚举与按行读取，不执行代码，不修改原文件；文件片段可能发送给所选模型。模型缺少授权时，Assistant 与 Activity 会展示同一审批卡片，由你选择目录或拒绝。
11. Run 默认预算为 24 步、64000 Token、300 秒活跃时间。预算用尽后暂停，Activity 显示消耗，点击“追加预算并继续”增加上限并从原检查点恢复。完整退出后手动继续；重新授权须在 Activity 选择原目录，目录身份变化时需要重新处理。

12. 侧栏“长期记忆”可搜索、查看原始用户证据、确认候选、修正和遗忘。新消息“我平时主要用 Swift 开发”自动保存为未确认事实；在项目内发送“确认项目数据库使用 PostgreSQL”，再发送“将项目存储方案从 PostgreSQL 改为 SQLite”，可查看现行决策、被替代版本和证据。新话题默认采用当前决策。
13. 自动提取仅识别保守句式，复杂表述可在 Inspector“从用户消息保存”，选择已加载的用户消息并核对主体、属性、内容及确认状态。归属纠正会停用错误证据；重新处理不会将旧决策的确认身份迁入目标项目。遗忘清理关联副本并保留抑制标记，“允许重新记住”只解除标记，不恢复旧正文。

路由使用本地中文分词、FTS5 和保守规则；歧义请求交由用户确认，任意同义改写可能需要手动选择。模型执行前保存实际采用的来源片段与版本，历史快照不会随源文本修改。

远程地址使用 HTTPS，HTTP 仅允许本机回环地址测试。Base URL 原样保留路径前缀，再追加 `/chat/completions`、`/responses` 或 `/messages`；需要 `/v1` 的服务，请在 Base URL 中填写它。不自动探测或切换 API 类型，不跟随 HTTP 重定向。

数据存放在 `~/.tandem/`：配置文件 `config.json` 权限 0600，目录 0700；Key 按产品基线明文保存，正常退出后保留，不写入业务 SQLite、聊天上下文或日志。聊天与话题使用 `tandem.sqlite`（WAL）。手工修改配置后重启或在设置中“重新加载”；保存遇到外部修改会拒绝覆盖。请勿提交本机配置文件。

关闭最后一个窗口后 Node 继续处理已接收的请求，点击 Dock 图标重新打开；使用 ⌘Q 完整退出会中断未完成请求。重新打开不会自动续跑，保留部分输出并提供手动重试。多窗口共享消息身份与顺序，各窗口焦点独立。

侧栏“运行状态”保留 M0 诊断入口，展示 Node PID、Ping/Pong、连接和重启次数，可手动断开重连或模拟 Runtime 崩溃。

## 检查

`pnpm run test` 包含配置冲突与权限、三种模型 API 的普通/流式契约、安全边界、队列/重试/历史恢复、SQLite 与 Swift 帧检查，以及真实 AssistantModel → Swift RPC → Node → 本机模拟模型端点的无窗口联调。联调从运行环境尚未启动时开始轮询，检查首份数据就绪时间、初始错误恢复和等待期间主线程任务持续调度。测试使用隔离目录，不读取真实 Key，不调用付费模型。需要允许本机 Unix Socket 和 HTTP listen；受限执行环境可能需要常规本地执行权限。

`pnpm run test:lifecycle` 构建后启动真实应用包，用应用内自检关闭最后一个窗口、验证持续心跳、重开窗口并完整退出，检查内嵌 Node 已结束。需可用的 macOS 图形登录会话；该检查会短暂显示窗口。

日志输出到标准错误；App 窗口保留最近 100 条 Host 日志。需保存日志时可直接运行：

```sh
dist/Tandem.app/Contents/MacOS/Tandem 2> /tmp/tandem-m0.log
```

M1 数据库首次启动先在 `~/.tandem/migrations/` 保存权限 0600、含完整历史的一致性保护副本，再事务迁移到 M2，保留原消息和顺序。保护副本不随当前数据库的删除操作自动清理；SQLite WAL、已有副本及云端留存不承诺物理擦除。M1 无法直接打开 M2 数据库，回滚须完整退出后从保护副本恢复；开发验证请使用隔离目录。M3 首次启动同样保存 Schema 2 保护副本后迁移至 Schema 3。目录授权由 Swift 持有，可撤销；完整退出后不自动恢复授权，重新选择同一资源后才能继续相关检查点。M4 首次启动保存 Schema 3 保护副本后迁移至 Schema 4；既有历史不自动批量提取，可从用户消息手动保存。自动提取及本地 FTS 的句式与召回边界见 M4 验收文档。手动备份恢复属于后续 Core 验收，当前尚未实现。实现与验证记录：[M0](docs/M0_开发与验收.md) / [M1](docs/M1_开发与验收.md) / [M2](docs/M2_开发与验收.md) / [M3](docs/M3_开发与验收.md) / [M4](docs/M4_开发与验收.md)。
