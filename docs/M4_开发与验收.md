# M4 开发与验收

日期：2026-11-13。依据产品基线 §6、§9.4、§10.1 的 M4 范围实施：Fact / Decision、用户证据、FTS5、Memory Inspector 和遗忘标记。不新增依赖；手动备份恢复属于后续 Core 验收。

## 交付与使用

- 新的已提交用户消息可提取长期事实及明确确认的项目决策；路由待确认输入不提取。普通聊天、提取和已授权读取不新增系统弹窗。
- 普通事实示例：“我平时主要用 Swift 开发”“我主要使用 TypeScript 编程”。自动保存关联原消息、Interaction 版本和项目范围，状态为现行事实，`confirmed_at` 留空；Inspector 显示“自动保存 / 用户陈述来源”。
- 项目决策示例：“确认项目数据库使用 PostgreSQL”“将项目存储方案从 PostgreSQL 改为 SQLite”。支持数据库 / 存储方案、技术栈、开发语言、部署方式。主体、规范化属性及作用域共同界定冲突；数据库 / 存储方案 / 存储 / database 使用同一个属性。新决策替代旧版本并保留历史、理由、证据和确认时间，不修改 Task 的目标或 Revision。
- 侧栏“长期记忆”支持搜索、查看版本和原证据、打开来源话题、确认候选、修正、遗忘和查看最小遗忘标记。从用户消息手动保存时，选择当前已加载且在可见范围内的原始消息，填写主体、属性和内容。未确认的决策及与现行内容冲突的普通事实作为候选；明确确认后才替代现行版本。
- automatic / pinned 可检索相关全局记忆及当前项目记忆；isolated 仅使用当前项目，不加载全局记忆或其他项目。现行决策通过结构化查询默认复原，普通事实通过中文分词和 FTS5 按需召回。候选、被替代及证据失效的版本不能充当现行知识。
- 每次构建上下文记录记忆 ID、版本、实际脱敏片段及原消息引用。后续普通更新不改写历史 Snapshot；查看历史仍按当前作用域校验。记忆作为资料传入，不赋予工具权限。
- 交互归属纠正与证据停用、清理 Outbox 在同一事务完成。只剩错误来源的记忆暂停使用；有独立有效证据时重新检查其归属、版本和确认资格。确认资格逐条绑定证据，未确认的陈述不能替代已失效的确认来源。旧决策不自动补位；原证据及历史快照可审计。
- 点击“重新处理”才按新范围提取；决策重新提取为候选，须重新确认。旧 Interaction 版本的保存请求被拒绝。受失效或替代记忆影响的在途 Run 取消，新派发及检查点恢复重新校验记忆有效性；任务目标与历史交付不被决策更新改写。
- 遗忘在同一事务保存标记、删除 Memory / Evidence / FTS、清理快照片段、检查点、工具调用副本、派生回答和对应报告引用。原用户聊天保留；关联旧 Run 被取消，迟到模型输出不能回写。无关来源保持不变。清理失败时数据库事务整体回滚。
- 来源校验沿后续回答与模型创建的 Task 继续追溯，不能借派生文本绕过原记忆的失效或 isolated 限制。遗忘还清理由受影响 Run 创建的 Task Revision 文本及其后续快照副本，保留任务身份，要求用户重新修改并确认标准；用户独立提交的任务要求不因此删除。
- 遗忘标记独立保存作用域、规范化键摘要、被阻止的原消息及派生消息标识、创建 / 解除时间，不保存记忆正文。提取提交前检查标记；重新处理、重启及纠正归属不能绕过原证据抑制。“允许重新记住”只解除标记，后续保存仍重新检查来源、作用域和冲突。独立的新用户证据不被自动全局禁记。
- 项目永久删除预览包含关联记忆数量，并清理记忆、证据及派生片段；保留其他项目、原外部文件和独立遗忘标记。

## 工程边界

`runtime/src/memory.ts` 实现本地规则提取、版本与证据校验、FTS、抑制标记和同步事务清理；复用现有 SQLite、事件游标、模型脱敏、Run 取消和 Context Snapshot。`MemoryView.swift` 提供 Inspector，不增加模型工具或后台模型请求。

自动提取采用锚定的保守句式，仅支持上述开发事实及明确项目决策。带假设、引用、示例、转述、不确定语气、多行和问句的输入不直接入库；文件、工具及模型输出不作为用户事实来源。无法识别的表达保留在聊天，可手动选择原用户消息保存；不是通用自然语言抽取器。既有 M0–M3 历史不在启动时批量提取。敏感信息和凭据拒绝保存，当前不提供敏感记忆授权流程。

自动事实继承原消息的有效作用域，不将项目事实提升为全局。手动保存及修正需要核验证据；“明确确认”是用户主动操作，不由模型或重新处理隐式执行。手动编辑时沿用相同主体与属性以形成同键版本链。

检索最多选取 12 条记忆、8 KiB 片段，现行决策优先，事实按 FTS 命中选择；使用现有 Run Token 预算约束实际请求。FTS 是可派生索引，命中仍需查验当前状态与有效证据。没有 Embedding、跨项目自动融合或自动关联任务调整。

Schema 3 → 4 前在私有 migrations 目录保存包含已提交 WAL 数据的一致性保护副本，权限 0600，执行完整性、外键、版本和同步检查后再事务迁移。迁移失败保留原 Schema 与数据。回滚旧版本须完整退出后从保护副本恢复。WAL、迁移副本、已有导出备份及云模型侧副本不承诺物理擦除；本次未实现对备份的改写或恢复流程。

## 验证

所有测试使用隔离临时目录、虚构 Key 和本机模拟模型，不访问真实 `~/.tandem` 或付费端点。

- M4 Node：直接事实与非确认状态、错误来源 / 不确定语气 / 敏感信息拒绝、去重与重启持久化、FTS 搜索；决策规范化、替代与冲突候选、跨 Session 来源快照；归属纠正、独立证据校验、旧版本保存拒绝和不迁移确认；遗忘、派生链清理、标记抑制与解除、失败事务回滚；automatic / pinned / isolated 边界；项目删除；Schema 保护副本、WAL 内容、迁移回滚与未来版本拒绝；实际模型输入跨 App 重启采用现行决策。
- 真实 Swift → Node 联调：Inspector 同一 RPC 的记忆保存、来源查询、新话题记忆 Snapshot、遗忘标记、已采用片段清理；保留三种模型协议、M2 路由与纠正、M3 原生文本读取与任务、崩溃和退出清理检查。
- Swift：保留文件安全、协议帧、模型设置、布局和未保存编辑防丢失回归。
