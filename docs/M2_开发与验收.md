# M2 开发与验收

日期：2026-11-13。依据产品基线 §2.4、§4、§5.6、§9 及 §10.1 的 M2 范围实施。M1 基线为 `15b1922`，默认目录继续使用 `~/.tandem/`。本阶段不新增依赖。

## 交付

| 入口 | 行为 |
| --- | --- |
| 项目 | 明确创建、名称与说明编辑、归档与恢复；归档保留历史并退出自动候选 |
| 永久删除 | 独立预览受影响的交互、消息、执行和共享快照；显式确认、十分钟有效期、提交前重新核对范围；不处理外部文件 |
| Assistant | 全局时间线，可按交互当前项目筛选；展示话题选择原因、项目归属与纠正记录 |
| Context Mode | automatic / pinned / isolated，显式应用范围；每个窗口独立焦点、版本和近期会话 |
| 待确认话题 | 输入先持久化并预留全局 sequence；歧义不创建 Session、Message、Run 或业务快照；可选择候选、其他范围内话题或新建话题 |
| 归属纠正 | 仅更改所选 Interaction 的输入与回答归属，其他交互及 Session primary Project 保持；停止旧执行；由用户点击重新处理 |
| 执行上下文 | 每个 Run 执行前固定实际使用的片段、来源 ID、内容哈希版本、项目、模式和顺序；可从回答查看 |

项目只在“项目”页面明确创建，或输入完整的“创建一个旅行项目”式命令时创建。提到“旅行项目”等主题不会自动创建项目。pinned / isolated 下不会借创建命令静默扩大项目范围，跨项目须先明确切换模式或项目。

## 实现与一致性

`runtime/src/context.ts` 集中实现 M2 项目、路由、Interaction、归属纠正、Snapshot 与删除；沿用 `service.ts` 的模型调用与调度，`store.ts` 执行 Schema 1 → 2 的事务迁移。SwiftUI 新增 `ProjectView.swift`，在聊天中加入范围控件、待确认卡片与快照查看。

接收事务保存脱敏输入、请求哈希、绑定模型、幂等键、保留的 Timeline sequence 和 route Outbox。路由只做本地查询，不调用模型或工具。确定路由后，提交事务重新验证项目、Interaction 与当前确认窗口的焦点版本，建立唯一用户消息和 Run，更新焦点及 run Outbox。用户消息复用预留 sequence；界面按 sequence 合并待确认输入与已提交消息，不重复展示。

Run 本身是持久执行队列，Outbox 标记路由和入队阶段；排队任务在轮到执行时才构建 Snapshot。启动把遗留 queued/running Run 与未消费 Outbox 标为中断，不自动提交 received/waiting_route，也不自动派发旧执行。待确认输入可在 Assistant 找回；确认动作可在另一窗口继续，事务只修改当前确认窗口的焦点。

同 Session 按输入因果顺序串行；快照排除后续输入、失败回答、其他项目内容、旧版本交互回答和包含越界来源的派生回答。实际模型输入由快照片段生成；历史查看读取保存的片段，不重新读取来源正文。来源更改不覆盖历史 Snapshot。M1 的历史 context_json 在迁移时保留为标明 `legacy_input` 的片段，以内容哈希标识版本，不伪造无法恢复的旧来源 ID。此类旧快照无法精确定位每个原消息，删除涉及旧会话时保守清理相关 legacy 片段和派生回答，预览列出影响范围。

归属纠正以 Interaction 版本防止过时提交，纠正记录、事件和停止标记在同一事务保存。旧在途请求尽力取消，迟到响应不覆盖消息或推进执行。手动重新处理关联同一用户消息并创建新的 Run/Snapshot，重复点击不会新增尝试；旧回答仍保留实际执行项目。仅修改展示归属不会把旧回答纳入新项目上下文。

删除预览同时涵盖当前归属及实际使用过该项目的 Run 所对应的交互。删除只移除范围内交互及其执行，共享 Session 中其他交互保留。其他 Snapshot 对被删来源的引用改为最小删除标记，显示“内容已删除，无法还原”；其 context_json 同步清理，并递归清理依赖被删片段的派生回答及后续快照；相关在途生成终止，避免迟到结果重新写回。受影响会话标题和路由候选副本同步清理，不从原始证据补回。保留中的历史快照仅在删除时清理片段，正常更新保持不变。删除后使所有窗口的历史游标失效并重新加载，清除客户端缓存中的已删消息。

归档只影响活动列表与自动候选，已有执行可继续，历史快照可在允许范围内查看。数据库变更前使用 VACUUM INTO 保存包含已提交 WAL 内容的一致性 Schema 1 保护副本到 `~/.tandem/migrations/`（目录 0700、文件 0600），校验 quick_check、外键和版本后才执行事务迁移。测试验证副本可恢复并重新迁移，也人为制造 DDL 冲突验证失败保留原表和版本。未知 Schema 拒绝启动；M1 无法直接打开 M2 数据库，须完整退出后从保护副本恢复。副本保留全部旧历史，不随当前数据库的删除操作自动清理；界面与 README 明确 SQLite WAL、保护副本及云端留存边界，不承诺物理擦除。

## 路由与范围

明确 Session / 新话题控制优先；支持临时插话与原话题恢复。历史候选使用 `Intl.Segmenter` 中文分词、SQLite FTS5 与词项重合排序；在查询及展示前限制项目和归档状态。候选说明包含匹配词、项目和最近活动时间。恢复意图候选不足，或候选差距较小时进入 CLARIFY；不会使用模型自报置信度。

这是保守的本地路由实现，词项分数不是校准概率。没有增加 embedding 或 LLM 路由器，任意同义改写可能需要用户选择；代码标记了这一限制。当前连续话题在缺少可靠切换信号时保持；独立主题可用“新话题 / 临时插话”明确指定。

isolated 必须明确绑定项目。项目缺失时保存待确认输入，不回退全局；跨项目显式恢复也被阻止，须用户明确切换范围。候选、候选说明、Session 列表、Snapshot 查看和上下文构建均检查范围。Assistant 的全局历史与项目浏览仍是本机展示视图，不作为模型上下文。M4 的长期记忆尚不存在，因此本阶段不加载任何全局记忆。

资源上限：项目共 200 个；状态查询每次展示最早 20 条可见待确认输入，处理后补上后续项；话题列表最近 100 条；历史消息每页 10 条。输入继续限制 8000 字符；Snapshot 最多 40 条因果消息，按 UTF-8 总字节上界 32 KiB 保守裁剪，保留本条输入并避免孤立 assistant 开头。没有引入模型专用 tokenizer；这是上下文资源保护参数，M3 的运行 token/步骤/时间预算仍后置。

## 验证

自动化测试全部使用临时数据目录、本机模拟 HTTP/SSE 和虚构 Key，不读取或迁移用户实际 `~/.tandem` 数据。

- M1 → M2 数据迁移：消息 ID / sequence、Focus 版本、旧输入快照保留；待执行请求中断；重复启动不重复迁移；外键完整。
- 路由：歧义输入不污染历史/焦点，重启仍待确认；预留顺序和确认幂等；过时版本拒绝；项目只按明确意图创建。
- 范围：isolated 无项目不派发；跨项目候选、话题恢复、旧快照与上下文被拦截；新请求只包含当前项目的实际片段。
- 纠正：其他交互不变；旧排队及在途执行停止；迟到输出不覆盖；反复纠正后的重新处理幂等；旧快照不随源正文更改。
- 删除：归档保留历史；删除要求预览和确认；过期范围拒绝；共享 Session 其他交互保留；相关快照片段清除，外键完整，窗口游标明确失效。
- 继续运行 M0/M1 全部 Node、Swift 协议测试与跨进程自检。实际 AssistantModel 联调新增待确认、isolated 快照、纠正与重新处理路径。
