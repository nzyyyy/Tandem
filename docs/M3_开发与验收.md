# M3 开发与验收

日期：2026-11-13。依据产品基线 §4.4、§4.7、§5、§8.6、§10.1 的 M3 范围实施。不新增依赖，不实现 M4 长期记忆。

## 交付与使用

- Assistant 输入区可勾选“持续任务”，在发送前填写预期交付物与逐条完成标准。普通聊天仍只创建 Run；模型处理多步骤工作时也可通过受校验的 `create_task` 建立 Task，要求有重要歧义时先澄清。
- Activity 展示 Task、当前修订、完成标准、完成依据、历次交付、Run 状态、模型、步骤、预算及实际上下文。点击“修改任务”明确提交新要求和新标准，停止旧 Run 派发，为同一 Task 创建新 Revision 和 Run；旧版本交付保留。
- 交付物复用同一 assistant Message，保存 Markdown 并支持打开和复制。`complete_task` 要逐条提供当前标准的完成依据；执行器检查当前 Revision、其他工具已完成、没有失败的必要工具步骤，并在同一事务保存消息、产物引用、完成依据和 Task 完成状态。模型普通回答结束不会自动完成 Task。
- Activity 的“授权只读目录”由用户触发 NSOpenPanel；目录归属当前项目（或全局未关联范围）。Swift 持有目录描述符，Node 只获得授权 ID、资源身份和名称。已有有效授权内的普通读取不逐文件审批。
- 缺少授权时模型可调用 `request_directory`，Run 等待审批。Assistant 和 Activity 展示同一请求，用户可“批准一次并选择目录”或“拒绝”；查看、切换话题、关窗均不批准。请求绑定 Invocation、工具版本、参数哈希、Run 主体、项目范围和十分钟有效期；批准后执行前仍重验授权。
- 每个 Run 默认 24 步、64000 Token、300 秒活跃时间。Activity 展示累计量和上限；预算触顶保留原 Run 与检查点，用户点击“追加预算并继续”才增加 24 步 / 64000 Token / 300 秒，不清零既有消耗。
- 关窗继续处理。完整退出中断在途与排队工作；重开后手动继续。预算暂停仍要求追加预算，旧审批失效后重新申请。完整退出后原生目录授权不自动恢复；在 Activity 点击“重新选择同一目录”，匹配原目录设备/文件身份后恢复原授权 ID，再继续检查点。目录替换不冒充原资源，需重新处理。Runtime 在 App 内崩溃后可重新登记仍由 Swift 持有的有效授权，但不自动续跑业务。

## 实现边界

`runtime/src/execution.ts` 保存 Task/Revision、RunStep、ToolInvocation、Approval、目录授权和预算；`service.ts` 沿用既有调度并执行模型→工具→模型循环。三种 API 都适配工具定义、工具调用、结果及 call ID；不探测、降级或自动换模型。已完成步骤由检查点复用，故障后的新尝试保留原模型绑定检查。等待审批、暂停或中断的早期输入会阻止同 Session 后续普通输入越过它；明确修订和取消立即生效。

每次模型调用引用独立 Snapshot，保存工具来源、原文件行号、版本和实际使用的脱敏片段；Run 保持初始 Snapshot 引用，不覆盖旧快照。文件内容标为不可信资料，不能提供指令、角色或授权。工具片段进入模型前再次脱敏。授权撤销后，旧文件快照不能查看或继续派发，含这些来源的派生回答不进入新上下文。

Swift 的 `DirectoryAccess` 通过持有目录 FD、逐级 `openat(O_NOFOLLOW)`、实际 FD 路径及 inode 检查约束范围；拒绝 `..`、绝对路径、符号链接和特殊文件。读取前后核对对象、路径、大小、mtime/ctime；只读源文件。授权复用和撤销均由 Swift 与 Node 双侧检查。此阶段不实现 security-scoped bookmark 或跨 App 重启自动授权。

工程参数：普通文件最大 1 MiB；一次读取最多 400 行 / 32 KiB UTF-8 输出，按字符边界截断并标明部分行、实际行号和未读完状态；目录枚举最多 100 项；Swift 读取上限 3 秒，Native Bridge 超时 5 秒。非法 UTF-8、控制字节二进制、PDF/Word 等不支持格式、文件变化、权限失效、大小超限分别返回明确错误。支持 UTF-8 BOM，不转换其他编码。

模型生成量每次最多 4096 Token，派发时预留输入和生成预算；有 usage 时按返回总量结算，缺少时以输入及输出 UTF-8 字节数保守估算并标注。失败请求保留已知输入和部分输出的估算消耗；停止生成不意味着收回服务端已消耗费用。时间计入请求等待和工具执行，不计等待审批及暂停。检查点最多 512 KiB；Activity 每次最多展示最近 200 个 Run 和 Task。

SQLite Schema 2 → 3 在私有 migrations 目录先保存含已提交 WAL 内容、权限 0600、经过完整性检查与同步的保护副本，再事务迁移。迁移失败保留旧表及版本。永久删除预览加入任务影响；删除清理 Task、工具结果、审批、步骤和检查点副本，并清除共享产物引用及完成依据，不删除外部目录或文件。备份、WAL 和云模型留存边界沿用 M2，不承诺物理擦除。回滚旧版本须完整退出后从对应 Schema 保护副本恢复。

## 验证

全部测试使用临时目录和虚构 Key，不访问用户真实 `~/.tandem` 或付费模型。

- Node：三种 API 工具结果关联、来源快照与凭据脱敏、任务完成/未完成/修订、单次审批、拒绝/过期/纠正失效、预算暂停及幂等追加、手动恢复、原目录身份重授权、复用工具检查点、授权撤销后的快照和派生内容过滤、项目删除和事务迁移回滚；继续运行 M0–M2 回归。
- Swift：UTF-8/BOM、原始行号与版本、只读不变、跨项目拒绝、路径与符号链接拒绝、目录替换、编码/格式/二进制错误、大小与条目上限、完整字符截断、授权撤销；继续运行已有协议与界面布局测试。
- 实际跨进程：AssistantModel → Swift RPC → Node → 本机模型 → Native Bridge → Swift 文件读取 → 模型工具结果 → Task Markdown 产物。保留冷启动、三种协议、M2 路由、断线、崩溃和退出自检。
- 应用包生命周期：关最后一个窗口后实际 Task 完成并持久化报告；重开同一窗口；完整退出中断另一在途请求，验证托管 Node 已退出及数据库状态。
