## 已选实施参数

- 交付架构仅 arm64。Node 24.22.2 / pnpm 11.22.0 / TypeScript 5.9.3，依赖以 `pnpm-lock.yaml` 锁定。构建和 Runtime 启动拒绝不匹配的 Node 版本。
- 使用 Node 内置 SQLite，无额外原生 addon；本机 SQLite 3.53.4，WAL、FTS5、事务提交与回滚由自动化测试验证。
- App 最低部署目标 macOS 14.0，与 SwiftUI API 需求对齐；检查当前 Node 二进制的 Mach-O 最低版本为 13.5，不提高 App 的 14.0 下限。当前仅在 macOS 27.2 实机验证，macOS 14 的实机兼容性仍待验证。
- 使用 SPM 构建 SwiftUI 可执行文件，脚本组装本地 `.app`，内置 Node 与编译后 JS；无 Host 第三进程，不依赖用户安装 pnpm 运行应用。
- 日志为时间戳与结构化事件名、PID、重连次数和重启延迟，不输出 bootstrap、认证凭据或请求正文；窗口仅保留最近 100 条 Host 日志，未实现日志文件轮转。

## IPC 与安全边界

传输格式为 **4 字节无符号大端长度 + UTF-8 JSON**，帧正文最大 64 KiB。Node 支持拆包和粘包，拒绝零长度、超长、非法 UTF-8 和非法 JSON；Swift 处理短读、短写、超时和中断。

请求包含 `protocolVersion: 1`、`requestId`、`method`、`payload`，Swift 同时发送当前无业务用途的 `idempotencyKey: null` / `expectedVersion: null`。响应保留版本与 requestId，成功为 `ok/data`，未知方法为 `ok: false/error`，错误含 `code/retryable`。认证或非法协议帧直接断开连接。

每次启动由 App 使用 `mkdtemp` 创建当前用户私有的 0700 临时目录，Node Socket 为 0600。App 在握手前通过 `getpeereid` 与 `LOCAL_PEERPID` 核对当前用户和本次启动的 Node PID，不仅依据路径信任对端。

Node 校验目录类型、所有权、权限和 bootstrap 中的父 PID，并要求每连接先完成一次随机凭据认证。凭据每次启动重新生成，只通过继承的 stdin 管道传递，不放在 argv、环境或日志。Node 侧依赖该能力凭据认证 App，不提供独立的 Darwin 对端 PID API；M0 不暴露工具或任意命令执行能力。正式代码签名身份与高风险工具授权不在本阶段实现，增加工具前仍需落实相应调用方与策略校验。

`hello` 返回 Node PID、架构与版本，Swift 再次验证；`ping` 返回 Pong。Socket 读写超时为 2 秒，Node 的空闲连接在 5 秒后断开。当前没有事件流、事件序列回放或 GAP_REQUIRED；这些随后续持久化状态实现，未以 Ping/Pong 替代业务恢复语义。

## 生命周期

- App 启动 Node，1 秒一次 Ping；连接中断时重新认证连接，连续失败达到 5 次后替换无响应的子进程。
- Node 异常退出按 1、2、4、8、16、30 秒退避重启，30 秒封顶；持续成功 5 次心跳后重置退避，防止启动即崩溃造成重启风暴。
- 关闭窗口不停止 App 或 Node；重开窗口展示同一 Supervisor 状态。
- 完整退出先禁止重启并取消通信循环，关闭 bootstrap 管道，发送 SIGTERM，最多等待约 2 秒后强制结束子进程，回收子进程并清理当前临时目录。I/O 超时会使退出额外等待最多约 2 秒。
- App 非正常退出时继承管道 EOF 使 Node 关闭 Socket；临时目录可能残留，但不含业务数据或凭据文件。不主动清扫其他运行实例的目录。
- M0 没有 Task、模型或工具执行，重新启动只恢复诊断心跳，不代表实现了业务任务的自动续跑。

## 验证记录

基础构建与检查命令：`pnpm install --frozen-lockfile`、`pnpm run build`、`pnpm run typecheck`、`pnpm run test`、`pnpm run test:lifecycle`。具体最终结果以本文末尾验收结果为准。

Node 检查覆盖中文与多字节内容、拆包粘包、非法帧、错误版本、未认证请求、错误凭据、未知方法、安全目录、Socket 权限以及 SQLite WAL/FTS5/事务。Swift 检查覆盖长度前缀、中文与帧上限、错误对端 PID 拒绝。进程联调使用生产 Supervisor，验证认证、Ping/Pong、同一子进程重连、强杀后替换子进程、停止后无残留或自动重启。

### 最终验收结果

以下均于上述本机环境执行通过：

| 检查 | 结果 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 通过，锁文件未发生漂移 |
| `pnpm run build` | 通过，生成含 Node 的 `dist/Tandem.app` |
| `pnpm run typecheck` | 通过，包含 Runtime 源码、Node 测试与 Swift 编译 |
| `pnpm run test` | 6 项 Node 测试、3 项 XCTest、1 项真实跨进程联调通过 |
| `pnpm run test:lifecycle` | 真实应用包启动、关窗持续心跳、重开、完整退出及 Node 无残留检查通过 |
| Mach-O / Info.plist | App 与内嵌 Node 均为 arm64；App 最低目标 14.0；plist 校验通过 |

窗口自检最初从 Swift 异步任务直接调用 AppKit 终止，导致嵌套事件循环阻塞测试退出。自检改为从 RunLoop Timer 触发退出后通过；生产退出仍走同一 `applicationShouldTerminate` 异步清理链路。此记录不将该次超时计作通过。
